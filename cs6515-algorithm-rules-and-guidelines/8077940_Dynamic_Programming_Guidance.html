Dynamic Programming Guidance

Staff Guidance Dynamic Programming Standard Template
Required solution components, rubric standards, and canonical LIS reference

Solutions for Dynamic Programming (DP) Homework are in a written format with required components. This post gives a general overview of the four mandatory parts of a DP solution. You will also see quiz and exam questions based on what constitutes a complete solution for DP.

General Rules

  • Algorithmic Paradigm: Submissions must be a Dynamic Programming approach to be eligible for points.
  • No Recursion or Memoization: Solutions must use an iterative bottom-up table fill approach. Recursive implementations or top-down memoization are not accepted.
  • 1-Based Indexing: Inputs are always indexed starting from 1, unless stated otherwise (i.e. A[0] is usually invalid).
  • Immutable Inputs: Inputs may not be modified — they are to be treated as immutable.
  • Table Indexing Flexibility: Tables may start from anywhere. If you need T[0] or T[-1] for a base case, this is valid as long as it is explicitly defined.
  • Primitive Values Only: Tables may only store primitive values: integers, decimals, characters, or Booleans. Never store lists, sets, or sequences inside table cells.

Required Sections (The 4-Part DP Template)

(a) Subproblem Definition

  • ALWAYS build on a subset of the input (e.g., $A[1 \dots i]$).
  • Conceptually, the subproblem should always be defined against "previous" subproblems and not on the entire input.
  • Is represented using words: "$T(i, j)$ is the ....."
  • Should use words from the problem statement without redefining their meaning.
  • May or may not require inclusion of the last element: ", including $A[i]$".

  • Course Convention on Inclusion: The lectures use the phrase "which includes $a[i]$" to add the constraint "element $a[i]$ must be used in the subproblem output." The phrases "which includes $i$" and "ending at $a[i]$" would also imply this constraint. These are not referring to the range of indices considered for the subproblem, $1, 2, \dots, i$, which is assumed inclusive $[1, i]$.

(b) Recurrence Definition

Rule #10: Read, absorb, and love Post #10 on Recurrence Relations!

  • Expressed using mathematical notation — no programming constructs and not in words.
  • The table gets a single mathematical definition for all entries — there is no logic/flow control structure other than stating a set of conditional definitions.
  • Defines the value of all table entries recursively in terms of smaller subproblems.
  • Any referenced table entry must also be well-defined (i.e. a reference for $T(i - 2)$ for $1 \le i \le n$ requires a definition for $T(-1)$ and $T(0)$).
  • It cannot be defined self-referentially (e.g. $T(i) = \max(T(i), \dots)$).
  • When base case(s) are necessary, include them and their applicable bounds (e.g. $T(i, 0) = 0$ for $1 \le i \le n$).
  • Always provide bounds for any variables used, scoped to where they are used.
  • Focus on table definitions, not a final solution (i.e. no return value here).

(c) Implementation Analysis (Parts 1, 2, 3, 4)

These parts should be based directly on the recurrence you developed in the previous section.

  1. State the number of subproblems in Big-O notation:
    • This scales similarly to space complexity.
    • A one-dimensional table ranging from indices $-1$ to $n$ would be $O(n)$.
    • Examples: $O(n)$, $O(n \cdot m)$.
  2. State the runtime to fill this table:
    • Always, always in this course — worst-case Big-O notation.
    • Example: $O(n^2)$.
  3. State how/where the final return is extracted from that table:
    • Examples: $\sum_{i=1}^n T(i)$, $\max_{1 \le i \le n} T(i)$, $T(n)$, $\max(T(n), T(n-1))$.
  4. State the runtime to extract the final return in Big-O notation:
    • Example: $O(n)$ if scanning all entries of $T$, or $O(1)$ if returning a specific corner cell like $T(n, W)$.

Tips and Tricks

  • Do Not Start With Code: You will be tempted to start with code. This is a terrible idea. Starting with code ensures your recurrence will be nearly impossible to craft. Do these sections in order — Dr. Vigoda does the same thing, and you will see how seamlessly the final solution comes together. Define a subproblem in words, translate it to the mathematical recurrence, and derive the analysis easily from that.
  • Recognize Canonical Paradigms: The lectures contain multiple foundational approaches (LIS, LCS, Knapsack, Chain Matrix Multiplication, etc.). When solving a new problem, first try to think of which approach makes the most sense to adapt for a solution to the new problem.

Example Canonical Solution

Below is an example of what a complete, full-credit DP solution looks like:

Longest Increasing Subsequence (LIS)

a. Define the entries of your table in words. E.g., $T(i)$ or $T(i, j)$ is ...

Let $T(i) =$ length of the longest increasing subsequence in $a[1 \dots i]$ which includes element $a[i]$.

b. State recurrence for entries of your table in terms of smaller subproblems.

$$T(1) = 1$$

$$T(i) = 1 + \max(\{0\} \cup \{T(j) : 1 \le j \le i-1 ext{ and } a[i] > a[j]\}) \quad ext{for } 2 \le i \le n$$

c. Implementation Analysis

  • (1) Number of subproblems: $O(n)$
  • (2) Runtime for table fill: $O(n^2)$
  • (3) Extraction mechanism: Return $\max_{1 \le i \le n} T(i)$
  • (4) Runtime of return extraction: $O(n)$

Discussion Key Takeaways & Staff Rulings

12 discussion threads • Staff clarifications
  • No Exam Template Sheet: Solution templates are NOT provided on exams. Students are expected to memorize and reproduce the 4 required sections: (a) Plain English Subproblem Definition, (b) Mathematical Recurrence + Base Cases, (c) Implementation Analysis (subproblems count, fill runtime, extraction expression, extraction runtime).
  • Omit Index Bounds in English Subproblem: Do not include index ranges (e.g. $1 \le i \le n$) in the English subproblem definition in Section (a). Section (a) defines the semantic meaning of an arbitrary entry $T(i)$ or $T(i, j)$. Bounds belong strictly in Section (b) on the recurrence.
  • Convention for Empty Maxima: In recurrences like LIS where no preceding element satisfies $a[i] > a[j]$, by mathematical convention $\max(\emptyset) = 0$, yielding $T(i) = 1 + 0 = 1$. It is good practice to explicitly state this convention or include $\{0\}$ in the set to avoid ambiguity.
  • Outputting Sequences vs Values: When asked to extract the sequence itself rather than just its value/cost, you do not need an auxiliary backpointer table. You can trace backward through the computed DP table in English or concise pseudocode. If you do define a parent table, you must account for its space and explain its updates.
  • Reductions to Known DP Paradigms: Reducing a problem to a known algorithm (e.g. solving Longest Palindromic Subsequence by reversing the string in $O(n)$ and running LCS in $O(n^2)$) is fully valid, provided the reduction time does not exceed the target complexity.
  • Infinity/Sentinel Padding: Initializing state boundaries with $+\infty$ or $-\infty$ (e.g., for $\min$ or $\max$ recurrences) or using sentinel indices like $T(0) = 0$ is valid as long as they are explicitly specified.
  • Correctness Proofs Omitted: Formal inductive proofs are not required in homework or exams; a mathematically sound recurrence with correct base cases and English description suffices.

    • Staff / Instructor Response

      are we allowed to use additional tables that we also fill using a dynamic programming approach

      You are not limited to a single table, nor are you limited to only 1D, 2D, or 3D tables.

      With that said, commonly when attempting to solve a problem, if you believe you need multiple tables, or if you think you need more dimensions, you may want to consider whether something about the problem that would allow a simplification has been missed.

      Additionally, any secondary/helper table is constrained to the same storage limitations as the primary table. Which is to say, you can't "use a second table" and start filling it with tuples or other non-primitive data.

      For (c3) "State how the return is extracted", if you need to extract a solution instead of returning a single value, you can describe it in a few sentences - it does not need to be in the limited math notation that the recurrence itself requires.
