Dynamic Programming (DP) Guidance

Exam 1 Focus DP1 · DP2 · DP3

Official staff instructions for structuring bottom-up dynamic programming solutions. On exams, solutions that use recursion, memoization sketches, or lack explicit subproblem definitions receive heavy penalties or zero credit.

1 Canonical 3-Part Solution Format

Every dynamic programming response must be structured strictly into the following three numbered sections:

Part 1: Subproblem Definition in Plain English

State precisely what an entry in your table represents. You must define:

  • Function/Table Name and Parameters: e.g., Let $T(i, j)$ be the optimal value...
  • English Meaning: What exact question does $T(i, j)$ answer? (e.g., "the minimum cost to multiply matrices $i$ through $j$", or "the maximum value obtainable using a subset of items $\{1, \dots, i\}$ with remaining weight capacity $j$").
  • Explicit Parameter Ranges: Give the discrete bounds for all indices (e.g., $0 \le i \le n$, $0 \le j \le W$).
Grading Pitfall: Never explain how to compute the subproblem in Part 1. Part 1 defines what the subproblem is; Part 2 defines how to calculate it.

Part 2: Recurrence Relation & Base Cases

Provide the mathematical formulation with base cases defined first:

  • Base Cases: Define all boundary conditions explicitly before the recurrence (e.g., $T(0, j) = 0$ for all $j \ge 0$, and $T(i, 0) = 0$ for all $i \ge 0$).
  • Recurrence Equation: Use clear mathematical notation ($\min$, $\max$, $\sum$).
  • English Justification for Every Choice: You must write 1–2 sentences explaining what each branch of the $\min$ or $\max$ represents in terms of the problem choices (e.g., "Branch 1 corresponds to excluding item $i$, in which case the value is $T(i-1, j)$; Branch 2 corresponds to including item $i$, consuming $w_i$ weight and gaining value $v_i$").
Non-Overwriting Rule: Table entries must not be overwritten or updated in place during execution. The recurrence must express the value of entry $T(i, j)$ purely as a function of already computed, distinct previous entries.

Part 3: Implementation Details & Runtime Analysis

Document the bottom-up table mechanics and complexity:

  • Data Structure & Table Size: e.g., "A 2D array $T$ of dimensions $(n+1) \times (W+1)$."
  • Iterative Fill Order: Specify the exact loop order (e.g., "Outer loop $i$ iterates from $1$ to $n$; inner loop $j$ iterates from $1$ to $W$"). Dependencies must be computed before they are queried.
  • Location of the Final Answer: Specify which entry or aggregation contains the final solution (e.g., "$T(n, W)$", or "$\max_{1 \le i \le n} L(i)$").
  • Worst-Case Runtime Breakdown: State the total number of table entries, work performed per entry, and the product: $$\text{Total Runtime} = (\text{Number of entries}) \times (\text{Work per entry}) = O(n \cdot W) \times O(1) = O(n W)$$

Graph Theory & DP on Graphs Guidance

Exam 1 & 2 GR1–GR4 · MF1–MF4

Official framework for graph reductions, approved graph black boxes, network flow formulations, and Dynamic Programming on graphs and DAGs.

1 Standard 4-Step Graph Reduction Framework

Graph theory exam problems require reducing the input problem to an approved canonical graph algorithm without modifying internal black box code. You must write your solution in 4 explicit steps:

  1. Graph Construction ($G' = (V', E')$):
    • Define what each vertex in $V'$ represents. State $|V'|$ in terms of the problem variables.
    • Define what each directed or undirected edge in $E'$ represents. State $|E'|$ in terms of the problem variables.
    • Define edge weights $w(e)$ or capacities $c(e)$, ensuring weights satisfy the preconditions of the chosen algorithm (e.g., non-negative for Dijkstra).
  2. Algorithm Invocation:
    • Name the permitted black box (e.g., "Run Dijkstra's algorithm on $G'$ starting from vertex $s$").
    • State all input arguments passed into the algorithm.
  3. Solution Extraction / Output Mapping:
    • Describe how to translate the output arrays or structures of the black box (e.g., `dist[]`, `prev[]`, min-cut cut-set, SCC components) back to the solution of the original problem.
  4. Total Worst-Case Runtime Breakdown: $$\text{Total Runtime} = O(\text{Graph Construction}) + O(\text{Black Box Execution}) + O(\text{Output Extraction})$$
Representation Assumption: All graphs are represented using standard Adjacency Lists. Building the graph takes $O(|V'| + |E'|)$ time, and iterating over neighbors takes $O(\text{deg}(v))$ time.

2 Dynamic Programming on Graphs & DAGs

Several fundamental graph algorithms are direct formulations of Dynamic Programming. Recognizing this connection simplifies both design and proofs:

A. Shortest & Longest Paths on DAGs in $O(V + E)$

Because a Directed Acyclic Graph (DAG) has no directed cycles, vertices can be linearized into a topological order in $O(V + E)$ using DFS reverse post-visit numbering. Once ordered, shortest or longest paths from source $s$ are solved via simple bottom-up DP:

  • Subproblem: Let $D(v)$ be the shortest path distance from $s$ to $v$.
  • Base Case: $D(s) = 0$; $D(v) = \infty$ for all $v \ne s$.
  • Recurrence: For each vertex $v$ taken in topological order: $$D(v) = \min_{(u, v) \in E} \{ D(u) + w(u, v) \}$$
  • Runtime: $O(V + E)$ — each vertex and edge is relaxed exactly once. Works even with negative edge weights!

B. Bellman-Ford as Dynamic Programming in $O(V \cdot E)$

Bellman-Ford solves single-source shortest paths on general graphs with arbitrary edge weights by constraining the number of edges:

  • Subproblem: Let $D(i, v)$ be the length of the shortest path from source $s$ to vertex $v$ using at most $i$ edges ($0 \le i \le |V|-1$).
  • Base Cases: $D(0, s) = 0$; $D(0, v) = \infty$ for $v \ne s$.
  • Recurrence: $$D(i, v) = \min \Big( D(i-1, v), \min_{(u, v) \in E} \{ D(i-1, u) + w(u, v) \} \Big)$$
  • Negative Cycle Detection: If a $|V|$-th relaxation pass yields $D(|V|, v) < D(|V|-1, v)$ for any vertex $v$, a negative weight cycle exists reachable from $s$.

C. Floyd-Warshall All-Pairs Shortest Paths in $O(V^3)$

Computes all-pairs shortest paths by expanding the permitted set of intermediate vertices:

  • Subproblem: Let $D(i, j, k)$ be the shortest path from $i$ to $j$ using intermediate vertices only from $\{1, \dots, k\}$.
  • Recurrence: $$D(i, j, k) = \min \Big( D(i, j, k-1), D(i, k, k-1) + D(k, j, k-1) \Big)$$

4 Network Flow Reductions & Min-Cut Rules

  • Max-Flow = Min-Cut: The value of the maximum flow from $s$ to $t$ equals the capacity of the minimum capacity $s$-$t$ cut $(S, T)$.
  • Finding the Min-Cut $(S, T)$ from Flow: After running Edmonds-Karp, construct the final residual graph $G_f$. Define $S$ as the set of all vertices reachable from $s$ in $G_f$, and $T = V \setminus S$. The minimum cut capacity is the sum of capacities of edges in original $G$ from $S$ to $T$.
  • Bipartite Matching Reduction: Given bipartite graph $G = (L \cup R, E)$:
    1. Add source $s$ and directed edges $s \to u$ for all $u \in L$ with capacity $1$.
    2. Direct all existing edges $u \to v$ from $L$ to $R$ with capacity $1$ (or $\infty$).
    3. Add sink $t$ and directed edges $v \to t$ for all $v \in R$ with capacity $1$.
    4. Run Edmonds-Karp in $O(V \cdot E)$. The Integrality Theorem guarantees integer flow $\implies$ max flow equals maximum matching cardinality.

Divide & Conquer (D&C) Guidance

Exam 1 Focus DC1 · DC2 · DC3

Official standards for Divide & Conquer solution narratives, Master Theorem evaluation, recurrence solving, and permitted D&C building blocks.

1 Required Parts of a D&C Solution

Every Divide & Conquer answer must be written in English narrative (no pseudocode or code unless specifically requested) with 3 mandatory parts:

Part 1: Algorithm Narrative Description

  • Base Case: State the stopping condition when $n$ is small (e.g., $n \le 2$) and the constant-time operation performed.
  • Divide Step: Explain how the input is divided into subproblems and their exact sizes (e.g., dividing array into two halves of size $\lfloor n/2 \rfloor$).
  • Recursive Calls: State exactly which subproblems are solved recursively and the number of calls ($a$).
  • Combine / Merge Step: Describe how the solutions to the subproblems are merged to produce the overall result.

Part 2: Informal Correctness Argument

Argue why your divide-and-combine logic produces the correct result. Mention base case correctness and explain why the combine step preserves the required invariants.

Part 3: Recurrence Relation & Worst-Case Runtime Analysis

  • State the recurrence in canonical form: $T(n) = a T(n/b) + O(n^d)$.
  • Explicitly identify parameters $a$, $b$, and $d$.
  • Compare $d$ to $\log_b a$ (or compare proliferation factor $a$ to size reduction $b^d$).
  • State which Master Theorem case applies and conclude with the final Big-O bound.
Prohibited on Exams: Do not write C++/Python code or raw pseudocode. Solutions must be clear, concise English narrative descriptions.

3 Master Theorem & Christian's Intuitive Approach

Given recurrence $T(n) = a T(n/b) + O(n^d)$ where $a \ge 1, b > 1, d \ge 0$:

Condition Christian's Intuition Work Distribution Resulting Complexity
$d > \log_b a \iff a < b^d$ Merge work shrinks geometrically at each level Top-Heavy (Root level dominates) $T(n) = O(n^d)$
$d = \log_b a \iff a = b^d$ Equal work performed across all $\log_b n$ levels Balanced ($O(n^d)$ per level $\times \log n$) $T(n) = O(n^d \log n)$
$d < \log_b a \iff a > b^d$ Leaf subproblems proliferate faster than work shrinks Bottom-Heavy (Leaves dominate) $T(n) = O(n^{\log_b a})$

NP-Completeness & Reductions Guidance

Exam 3 Focus NP1 · NP2 · NP3 · NP4

Official principles governing polynomial-time reductions, directionality rules, certificate verification, and approved NP-complete black boxes.

1 The Cardinal Direction Rule of NP Reductions

FATAL EXAM ERROR — The Cardinal Direction:
To prove that target problem $B$ is NP-complete, you MUST reduce an already-known NP-complete problem $A$ to target problem $B$ ($A \le_P B$).
If you reduce $B \le_P A$, you prove only that $B$ is no harder than $A$ (i.e., that $B \in NP$), which earns 0 points for NP-hardness!

The Core Logic: An NP-complete problem $A$ is known to be intractable. If a polynomial-time algorithm existed for $B$, then through $A \le_P B$, we could solve $A$ in polynomial time, proving $P = NP$. Hence $B$ must be at least as hard as $A$.

2 Canonical 4-Step NP-Completeness Proof Rubric

  1. Show $B \in NP$ (Certificate & Verifier):
    • Define a polynomial-length certificate $C$ (e.g., a set of vertices $S \subseteq V$, or a truth assignment to boolean variables).
    • Describe a deterministic polynomial-time algorithm that takes an instance of $B$ and certificate $C$, and verifies whether $C$ is a valid solution in $O(n^k)$ time.
  2. Select Known NP-Complete Problem $A$:
    • Choose an approved NP-complete problem from the course catalog that structurally matches target problem $B$.
  3. Construct the Polynomial-Time Reduction Function $f$:
    • Describe a function $f$ that transforms any instance $x$ of problem $A$ into an instance $f(x)$ of problem $B$.
    • Argue that the transformation runs in polynomial time relative to the size of $x$.
  4. Bidirectional Correctness Proof ($x \in A \iff f(x) \in B$):
    • Forward Direction ($\implies$): Assume $x$ is a YES-instance of $A$ (has a solution). Prove that $f(x)$ must be a YES-instance of $B$.
    • Reverse Direction ($\impliedby$): Assume $f(x)$ is a YES-instance of $B$. Prove that $x$ must be a YES-instance of $A$ (or prove the contrapositive: if $x$ is NO, then $f(x)$ is NO).

Linear Programming (LP) & Duality Guidance

Exam 3 Focus LP1 · LP2 · LP3 · LP4

Official instructions for LP formulations, canonical forms, duality rules, simplex mechanics, and Integer Linear Programming (ILP).

1 Canonical 4-Element LP Formulation Format

Every LP formulation response must specify four explicit components:

  1. Decision Variables with Clear Units: Explicitly state in English what each variable $x_i$ represents and its units (e.g., "$x_i$ = number of gallons of chemical $i$ produced per day").
  2. Objective Function: Specify $\max$ or $\min$ of a strictly linear combination: $$\max \sum_{j=1}^n c_j x_j \quad \text{or} \quad \min \sum_{j=1}^n c_j x_j$$
  3. Linear Constraints: A system of linear inequalities or equations ($\le, \ge, =$): $$\sum_{j=1}^n a_{ij} x_j \le b_i \quad \text{for each resource } i$$
  4. Explicit Variable Bounds / Non-Negativity: $$x_j \ge 0 \quad \text{for all } j \in \{1, \dots, n\}$$
Zero Point Pitfall: Omitting the non-negativity constraints ($x_j \ge 0$) causes the LP to be unbounded or meaningless, resulting in substantial point deductions.

2 Duality Rules & Matrix Transformation Recipe

The standard primal-to-dual mapping pairs variables with constraints and vice versa:

Primal Linear Program (Maximization) Dual Linear Program (Minimization)
Objective: $\max \mathbf{c}^T \mathbf{x}$ Objective: $\min \mathbf{b}^T \mathbf{y}$
$m$ Constraints: $\mathbf{A} \mathbf{x} \le \mathbf{b}$ $m$ Dual Variables: $y_i \ge 0$
$n$ Variables: $x_j \ge 0$ $n$ Dual Constraints: $\mathbf{A}^T \mathbf{y} \ge \mathbf{c}$
Equality constraint: $\sum a_{ij} x_j = b_i$ Unconstrained dual variable: $y_i \in \mathbb{R}$

Fundamental Duality Theorems:

  • Weak Duality: If $\mathbf{x}$ is primal feasible and $\mathbf{y}$ is dual feasible, then $\mathbf{c}^T \mathbf{x} \le \mathbf{b}^T \mathbf{y}$. Any dual feasible solution provides an upper bound on the primal maximum.
  • Strong Duality: If either the primal or the dual has an optimal finite solution, then both do, and their optimal values are identical: $$\max \mathbf{c}^T \mathbf{x}^* = \min \mathbf{b}^T \mathbf{y}^*$$
  • Infeasibility Duality: If primal is unbounded, dual is infeasible. If primal is infeasible, dual is either unbounded or infeasible.

3 Integer Linear Programming (ILP) Complexity

  • Standard LP: Solvable in polynomial time using Interior Point methods or the Ellipsoid algorithm. The Simplex algorithm is worst-case exponential but runs efficiently in practice.
  • Integer Linear Programming (ILP): When variables are restricted to integer values ($x_j \in \mathbb{Z}$), the problem becomes NP-hard. Many NP-complete problems (e.g., 3-SAT, Vertex Cover) can be encoded directly as ILPs.

2 Course Readiness & Math Review

  • Mathematical Induction: State base case ($n=1$), formulate induction hypothesis ("Assume claim holds for all $k \le n$"), and prove inductive step for $n+1$.
  • Logarithm Rules: $\log(a \cdot b) = \log a + \log b$; $\log(a^b) = b \log a$; $a^{\log_b c} = c^{\log_b a}$; $\log_b a = \frac{\ln a}{\ln b}$. Note that in computer science, $\log$ defaults to base 2 unless specified.
