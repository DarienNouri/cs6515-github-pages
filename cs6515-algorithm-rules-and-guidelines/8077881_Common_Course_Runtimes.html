Runtime Analysis Standards

When performing runtime analysis for this course, we expect the analysis to be presented as the worst-case runtime analysis, presented in fully simplified Big-O notation.

Simplification Standard: For example, O(2n + 3n) is expected to be presented as $O(n)$.

As most assessable material for this course is written, this post exists to present the runtimes associated with common actions you may describe in your algorithms.

Default Actions & Assumptions: When no supporting details are presented for special handling in a submission, the default action (underlined) and associated runtimes will prevail.

For the runtimes presented below, $n$ represents the length or size of the object being used.

Lists & Arrays

In the context of the course, we will treat lists as standard arrays, indexable by integers starting at 1.

Operation Description / Variant Worst-Case Cost
Creating a list Empty $O(1)$
Creating a list With initial contents $O(n)$
Adding an item to a list Appends to the end (default) $O(1)$
Adding an item to a specific non-tail location of a list Requires shifting subsequent elements $O(n)$
Remove an item from a list Swap tail element and pop (default) $O(1)$
Remove an item from the list while maintaining order Requires shifting elements left $O(n)$
Check the length of a list Via counting (default) $O(n)$
Check if a list contains an element Via scanning (default) $O(n)$

Hash Table / Hash Set / Map / Set

While common and practical for software development, these data types have worst-case performance that generally makes them undesirable.

Course Warning: Unless the problem gives you data in this format (typically as a set), you are unlikely to need this.

Operation Description / Variant Worst-Case Cost
Creating a hash table Empty (default) $O(1)$
Creating a hash table with initial contents Worst-case collisions during insertion $O(n^2)$
Adding an item to a hash table Default (worst-case bucket collision traversal) $O(n)$
Remove an item from a hash table Default $O(n)$
Check the length of a hash table Via counting (default) $O(n)$
Check if a hash table contains an element Via scanning (default) $O(n)$

Graphs (Adjacency Lists)

In this course, we will always treat graphs as adjacency lists, with an indexable list of vertices each pointing to a linked list of adjacent vertices. You can assume you know $n$ (number of vertices $|V|$) and $m$ (number of edges $|E|$).

Operation Scope & Details Worst-Case Cost
Traversing a graph Includes reversing, copying, subgraphing, or anything that requires working with all vertices and edges in a graph $O(n + m)$
Operating on a single vertex $v$ Includes find, read, removal $O(1)$
Operating on all (or a subset of) vertices $V$ Includes find, read, removal $O(n)$
Operating on a single edge $e = (u, v)$ This is due to the need to traverse up to $n$ vertices in the adjacency list for vertex $u$, to find and operate on adjacency $v$. (Includes find, read, removal) $O(n)$
Operating on all edges $|E|$ Includes find, read, removal $O(n + m)$
Accessing properties of an edge or vertex This assumes you already have access to the vertex or edge itself — that is, you have paid the runtime costs above for finding that vertex/edge (e.g. weight, color, cost, capacity, etc.) $O(1)$

Special Note About Simplifications

If you KNOW something about the connectivity of the graph (e.g. MST, Flow, or the problem states it), it is possible to simplify some runtimes:

  • We know the graph is connected and $m \ge n - 1$: $$O(n + m) = O(m + m) = O(2m) = O(m)$$
  • We know the graph is a clique and $m = \frac{n(n - 1)}{2}$: $$O(n + m) = O(n + n^2) = O(n^2)$$

Discussion Key Takeaways & Staff Clarifications

4 discussion threads • Staff rulings
  • $O(1)$ List Removal via Swap-and-Pop: $O(1)$ removal assumes you already have the index $i$. If you must search for a value first, scanning takes $O(n)$. Crucially, swapping the element at index $i$ with the tail element and popping it destroys relative ordering. If sequential relative order must be preserved, remaining items must be shifted left, which costs $O(n)$.
  • Tombstone Array Removal Hazard: Marking deleted elements with "tombstone" values avoids shifting, but students frequently blunder by picking a tombstone value that is also a valid input value.
  • DP Table Complexity: DP tables follow standard array rules. Initializing/creating a 1D vector $T[1 \dots n]$ takes $O(n)$ time; cell lookup $T[i]$ takes $O(1)$. Initializing a 2D table $T[1 \dots n, 1 \dots n]$ takes $O(n^2)$ time; cell lookup $T[i, j]$ takes $O(1)$.
  • Adjacency List Single Edge Lookup is $O(n)$: Finding vertex $u$ is $O(1)$ via array index, but finding whether edge $(u, v)$ exists requires scanning $u$'s linked list of neighbors. In a dense or adversarial graph, vertex $u$ can have up to $n - 1$ edges, resulting in worst-case $O(n)$.
  • No Exam Formula Sheet: Basic runtime analysis and data structure mechanics are prerequisite competencies tested directly on exams; no reference sheet or note-card will be provided for Exam 1.

    • Staff Explanation

      You cannot.

      Finding $u$ takes $O(1)$, but finding where $v$ is under $u$ is what takes the time.

      The adjacency list is a list of linked lists, and the endpoints of the edges are stored in the linked list portion, which requires traversal to discover what it contains.

      For a general graph, any given vertex may have at most $n-1$ edges in its linked list, giving us the worst case runtime for a single edge of $O(n)$ listed above.
