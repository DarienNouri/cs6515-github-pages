Usable Black Boxes for Graphs

Staff Guidance #192 Graph Theory Black-Box Whitelist
12 approved graph black boxes, exact I/O interfaces, and canonical runtimes

For the graphs section, you must use the algorithms presented in the course materials to help you solve presented problems. Solutions in this section must use one (or a combo) of the black boxes to solve the presented problem.

Black Box Policy & Output Interface Standards

Strict Invariance: Providing full implementation details of one of these black boxes and adding in a twist or in-line tracking will be treated as an unpermitted modification. Only the algorithms explicitly listed here may be used.

All runtimes below are presented assuming $n = |V|$ (number of vertices) and $m = |E|$ (number of edges). All outputs are produced as $n$-sized lists containing an entry for each vertex in the graph, and are able to be indexed by vertex in $O(1)$ time to read their contents, unless otherwise noted.

1. Depth-First Search (DFS)

Runtime: $O(n + m)$ Graph: General (Directed or Undirected)
DPV pp. 83–91 • GR1.3, GR1.6
  • Input:
    • A simple graph in adjacency list format.
    • A starting vertex (optional; if omitted, starts from an arbitrary vertex via adjacency list order).
  • Internal (not accessible after run):
    • visited[]: Set to true for all touched vertices via internal subroutine Explore.
  • Output:
    • ccnum[]: Connected component number of each vertex (vertices reachable from starting vertex have component number 1).
    • prev[]: Parent vertex in the DFS traversal tree (unreachable vertices and starting vertex have parent nil).
    • pre[]: Pre-visit clock timestamp.
    • post[]: Post-visit clock timestamp.
  • Common Uses: Finding connected components, cycle detection (back-edges), producing paths to reachable vertices.

2. Topological Sort

Runtime: $O(n + m)$ Graph: DAG (Directed Acyclic Graph)
DPV pp. 91–93 • GR1.7
  • Input: A simple, directed, acyclic graph (DAG) in adjacency list format.
  • Output:
    • order[]: A list of vertices sorted in topological order from source to sink. (Note: Indexed numerically $1 \dots n$, rather than by vertex ID).
    • All standard outputs from DFS (pre[], post[], prev[]) are also available.
  • Common Uses: Ordering prerequisite tasks, cycle detection in directed graphs (topological sort fails if a back-edge exists).

3. Strongly Connected Components (SCC / Kosaraju)

Runtime: $O(n + m)$ Graph: Directed
DPV pp. 93–99 • GR1.8
  • Input: A simple, directed graph in adjacency list format.
  • Output:
    • $G^{SCC} = (V^{SCC}, E^{SCC})$: Strongly connected components metagraph in adjacency list format. By construction, $G^{SCC}$ is a DAG with vertices sorted in reverse topological order (sink to source).
    • ccnum[]: Maps each vertex to its strongly connected component identifier.
  • Common Uses: Condensing arbitrary directed graphs into DAGs, 2-SAT satisfiability verification.

4. Breadth-First Search (BFS)

Runtime: $O(n + m)$ Graph: Unweighted (Directed or Undirected)
DPV pp. 105–108 • GR2.1
  • Input: A simple unweighted graph in adjacency list format, and a starting vertex $s$.
  • Output:
    • dist[]: Unweighted hop distance from starting vertex $s$ to all vertices ($\infty$ if unreachable).
    • prev[]: Parent vertex in BFS shortest-hop tree (unreachable vertices and $s$ have parent nil).
  • Common Uses: Fewest-hop shortest paths, finding shortest cycles, testing for bipartiteness (2-coloring).

5. Dijkstra's Algorithm

Runtime: $O((n + m) \log n)$ Weights: Non-negative ($w \ge 0$)
DPV pp. 108–115 • GR2.2
  • Input: A simple graph in adjacency list format, a starting vertex $s$, and non-negative edge weights $w(u, v) \ge 0$.
  • Output:
    • dist[]: Weighted shortest path distance from $s$ to all vertices ($\infty$ if unreachable).
    • prev[]: Parent vertex in shortest path tree.
  • Common Uses: Single-source shortest paths on non-negatively weighted graphs.

6. Bellman-Ford (BF)

Runtime: $O(n \cdot m)$ Weights: Arbitrary (Can be Negative)
DPV pp. 115–119 • GR2.3
  • Input: A simple directed graph in adjacency list format, starting vertex $s$, and arbitrary edge weights.
  • Output:
    • dist[]: Shortest path distance from $s$ after $n - 1$ relaxation rounds ($\infty$ if unreachable).
    • prev[]: Predecessor on shortest path.
    • has_negative_cycle: Boolean indicating whether a negative-weight cycle is reachable from $s$ (detected on $n$-th iteration).
  • Common Uses: Shortest paths with negative edge weights, negative cycle detection.

7. Floyd-Warshall (FW)

Runtime: $O(n^3)$ All-Pairs Shortest Paths
DPV pp. 169–172
  • Input: A simple graph in adjacency list format with edge weights (no negative cycles).
  • Output:
    • dist[][]: 2D matrix containing shortest path distances between all pairs $(u, v)$ ($\infty$ if unreachable).
    • prev[][]: 2D predecessor matrix for path reconstruction.
  • Common Uses: All-pairs shortest path computation, transitive closure, graph diameter.

8. Kruskal's Algorithm

Runtime: $O(m \log n)$ Minimum Spanning Tree (MST)
DPV pp. 128–137 • GR3.6
  • Input: A simple, connected, undirected graph with real edge weights.
  • Output: edges[]: A list of $n - 1$ edges representing a minimum spanning tree.
  • Common Uses: Finding minimum spanning trees, minimum bottleneck spanning trees, clustering.

9. Prim's Algorithm

Runtime: $O((n + m) \log n)$ Minimum Spanning Tree (MST)
DPV pp. 137–140 • GR3.7
  • Input: A simple, connected, undirected graph with real edge weights.
  • Output: prev[]: Parent pointers of each vertex forming an MST rooted at an arbitrary starting vertex.
  • Common Uses: Finding an MST growing from a designated root vertex.

10. Ford-Fulkerson (FF)

Runtime: $O(m \cdot C)$ Capacities: Positive Integers
DPV pp. 198–207 • GR4.2
  • Input: A simple, connected, directed graph, positive integer edge capacities $C$, source $s$, and sink $t$.
  • Output:
    • flow[]: Flow assignment $f(u, v)$ for each edge maximizing total flow from $s$ to $t$.
    • max_flow: Total flow value $v^*$.
    • min_cut: Partition $(S, T)$ where $S$ is the set of vertices reachable from $s$ in the final residual graph $G_f$.
  • Common Uses: Maximum flow with small integer capacities, finding min-cuts, maximum bipartite matching.

11. Edmonds-Karp (EK)

Runtime: $O(n \cdot m^2)$ Capacities: Arbitrary Positive Real
DPV pp. 207–210 • GR4.3
  • Input: A simple, connected, directed graph, positive real edge capacities, source $s$, and sink $t$.
  • Output:
    • flow[]: Flow assignments $f(u, v)$ maximizing flow from $s$ to $t$.
    • max_flow: Total flow value $v^*$.
    • min_cut: Partition $(S, T)$ derived from residual reachability.
  • Common Uses: Maximum flow with large integer or irrational/real capacities where augmenting paths are chosen via shortest hops (BFS).

12. 2-SAT

Runtime: $O(n + m)$ Input: 2-CNF Boolean Formula
DPV pp. 99–102 • GR1.9
  • Input: A boolean formula in Conjunctive Normal Form (CNF) where each clause has at most 2 literals ($n$ variables, $m$ clauses).
  • Output:
    • assignments[]: Truth value assignments $\{T, F\}$ for each variable that satisfy the formula.
    • Returns "UNSATISFIABLE" if any variable $x$ and its negation $ eg x$ lie in the same strongly connected component.
  • Common Uses: Testing 2-satisfiability, resolving paired constraint systems, 2-coloring interval graphs.

Discussion Key Takeaways & Staff Clarifications

9 discussion threads • Staff rulings
  • Algorithm Names Given on Exam 2: Unlike Exam 1, the names of graph black-box algorithms are provided on Exam 2. However, you must know their exact input/output interfaces, runtime complexities, and applicability constraints.
  • Max Flow Algorithm Output Details: Calling Ford-Fulkerson or Edmonds-Karp returns both the aggregate maximum flow value and the individual flow allocations $f(e)$ on each edge, as well as the $(S, T)$ min-cut.
  • Dijkstra vs. Uniform-Cost Search (UCS): Always refer to Dijkstra's Algorithm as "Dijkstra" rather than "UCS" to ensure seamless grading against official rubric benchmarks.
  • Tracing by Hand on Exams: Exam 2 frequently asks students to trace standard algorithms (e.g. Dijkstra relaxation steps, Kruskal union-find steps, augmenting path augmentations in FF) on a provided toy graph.
  • DFS Traversal Order: Never assume alphabetical tie-breaking in DFS; visitation order is determined solely by the ordering of vertices in the underlying adjacency list.
  • Output Array Indexing: All outputs (dist[], prev[], ccnum[]) are indexed in $O(1)$ by vertex ID, except Topological Sort's order[] which is indexed $1 \dots n$ from source to sink.
  • Kruskal's Sorting Runtime: Sorting $m$ edges takes $O(m \log m) = O(m \log n)$ because $m \le n^2 \implies \log m \le 2 \log n$. Together with union-find, Kruskal's total runtime is $O(m \log n)$.
  • Prim's vs. Dijkstra Complexity: Both Prim's and Dijkstra's algorithms use a min-heap priority queue over adjacency lists, yielding identical $O((n + m) \log n)$ runtime bounds.
