Divide and Conquer Guidance

Staff Guidance Divide & Conquer Standard Template
Required solution format, narrative rules, and Master Theorem standards

Below you will find official guidance on how you should approach solving Divide & Conquer (D&C) problems in CS6515. In cases where legacy lecture material differs in format or content, this guidance supersedes those examples.

Fundamental Rules

  • D&C Paradigm Required: Submissions must be a genuine Divide & Conquer approach to be eligible for points.
  • Narrative Prose Only: When asked to describe your solution in words, you may not use code or pseudocode.
  • Strict Subproblem Reduction: Each recursive subproblem must strictly reduce the problem size (e.g. $n/2$, $n/b$).
  • Beat Brute Force: Your algorithm must strictly improve upon the naive or brute-force runtime.

Permitted Black Boxes: You may leverage standard black-box algorithms: Binary Search, Merge Sort, Median of Medians (FastSelect), or FastMultiply / Karatsuba. (See the Usable D&C Algorithms guide for details).

Modifying Black Boxes: You may modify a known algorithm (adapting its divide-and-conquer pattern to suit your needs). If you do so, you must:
1. Account for the runtime impact of any modifications in your recurrence.
2. Explicitly justify why your modifications solve the problem correctly.

Required Parts of a D&C Solution (The 3-Part Rubric)

(a) Algorithm

  • Describe "how" to solve the problem in words (narrative / paragraph form).
  • Bulleted conceptual steps are fine, but pseudocode or programming syntax is not allowed.

  • No Pseudo-prose: "Pseudocode" includes line-by-line restatement of code into English (e.g. 1. Let x = 0; 2. For each element...). If you find yourself using many nested bullets, you are likely converting code into words rather than writing a high-level conceptual narrative.

  • Must include all steps from base cases to the final return value.
  • If you modify a known algorithm, you must detail the exact modifications.

(b) Justification of Correctness

  • Describe "why" your algorithm solves the problem in words (narrative).
  • This is an informal justification, not a tedious formal inductive proof.
  • Explain why the problem space reduces on each step, why base cases hold, and why your choice to branch left or right is guaranteed to preserve the solution.
  • If you modified a known algorithm, explain why that modification is correct and effective.

(c) Runtime Analysis

  • Analyze all non-$O(1)$ steps of the algorithm in Big-O notation.
  • Always worst-case Big-O in CS6515.
  • State the recurrence relation: $$T(n) = a T(n/b) + O(n^d)$$
  • Solve the recurrence using the Master Theorem, stating the values of $a$, $b$, and $d$, and comparing $\log_b a$ against $d$.
  • You may assert known unmodified black-box runtimes without further justification (e.g. Merge Sort is $O(n \log n)$, FastSelect is $O(n)$).
  • If a black box is modified, you must justify the runtime impact of the modifications, even if there is no change to asymptotic complexity.
  • Must provide an overall final runtime in fully simplified Big-O notation.

Keep Sections Strictly Separate: Address each of the three components ((a) Algorithm, (b) Correctness, (c) Runtime) separately. There is no implicit justification of correctness inside the algorithm steps; correctness must be explicitly stated in Part (b).

Steps to Developing a D&C Solution

  • Identify the Algorithmic Pattern:
    • Sorted input: Usually adapts Binary Search ($T(n) = T(n/2) + O(1) \implies O(\log n)$).
    • Unsorted input: Usually adapts Merge Sort ($T(n) = 2T(n/2) + O(n) \implies O(n \log n)$) or FastSelect ($T(n) = T(n/5) + T(7n/10) + O(n) \implies O(n)$).
    • Polynomials, convolution, or multiplication: Usually adapts FFT ($O(n \log n)$) or FastMultiply ($O(n^{\log_2 3})$).
  • State Black Box Modifications: Specify which parts change, along with updated input and output specifications.
  • Narrate Algorithm Steps: Detail base cases, divide steps, recursive calls, and combine logic. Always return what the problem requests.
  • Prove Correctness:
    • Why does this black box apply to the problem?
    • Why does the subproblem size decrease on every round?
    • Why does the decision to eliminate half the input never discard the target element?
  • Analyze Runtime: Set up recurrence and solve via Master Theorem.

Discussion Key Takeaways & Staff Clarifications

12 discussion threads • Staff rulings
  • Direct Master Theorem Application: Once you establish and justify your algorithm recurrence $T(n) = a T(n/b) + O(n^d)$, you can directly invoke the Master Theorem cases without re-proving them. State $a$, $b$, $d$, compare $\log_b a$ to $d$, and state the resulting Big-O.
  • Asymptotic Optimality on Exams: D&C solutions must achieve the target asymptotic bound. If a problem expects an $O(\log n)$ binary search adaptation, an $O(n)$ linear scan receives minimal partial credit.
  • Strict Separation of Rubric Sections: Keep Section (a) Algorithm, Section (b) Correctness, and Section (c) Runtime clearly separated with distinct headings. Do not mix correctness claims into the algorithm description.
  • Modified vs. Unmodified Black Boxes: If using a black box unmodified (e.g. standard Merge Sort), state its inputs, outputs, and runtime ($O(n \log n)$). If modifying it (e.g. altering the merge step or stopping recursion early), you must explicitly describe the changes, explain why they preserve correctness, and re-analyze the runtime impact.
  • No Line-by-Line Pseudocode: Writing code disguised as bulleted English (e.g. 1. let x = 0; 2. for i from 1 to n:) is penalized. Write clear, conceptual algorithmic steps in prose.
  • FFT Scope: Fast Fourier Transform (FFT) is introduced in D&C lectures for polynomial multiplication, but check current syllabus announcements regarding exam coverage.

  • Student Question

    On a real exam, will we be graded on optimality for a D&C problem? For example, lets say we didn't have the fast multiplication algorithm in the lectures and were asked to create a D&C algorithm for multiplication. Lets say I define an algorithm in D&C format and analyze it correctly, but I didn't know the trick for the O(log2(3)) solution so my solution was O(n^2)

    Would I lose points for this?

    • Staff / Instructor Response

      Optimal approaches (or at least, beating a naive approach) are extra important for Divide and Conquer, since that's the whole point of doing a Divide and Conquer solution. If you're searching through a sorted list and you come up with a divide and conquer approach that's O(n), there's no point in going through all the extra dividing and conquering steps since an O(n) linear scan can accomplish the same things. Failing to beat a brute force or naive approach means big penalties, and exams are graded in the same way homeworks are.

      However, Integer Fast multiplication (and FFT, which is also divide and conquer) is something very clever to have developed in a vacuum. Coming up with something that clever would be a bit much to ask for on an exam. But at the same time, since it's covered in the lectures, asking you to use it or to pattern off of it is fair game.
