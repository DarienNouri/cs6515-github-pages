Breadth-first search: shortest-path layers

BFS explores an unweighted, undirected graph in increasing distance from a source. The FIFO queue holds discovered vertices whose adjacency lists still need to be processed. A vertex’s distance is fixed the first time it enters the queue. BFS runs in O(|V| + |E|) with adjacency lists; it minimizes the number of edges, so weighted shortest paths require a different algorithm.

Graph and complete BFS walkthrough

Vertices: A, B, C, D, E, F. Undirected edges: A–B, A–C, B–D, B–E, C–E, D–E, D–F, E–F. The source is A, and neighbors are examined alphabetically.

  1. Set distance(A) = 0 and queue = [A]. All other distances begin at infinity.
  2. Remove A. Discover B and C at distance 1; queue = [B, C]. Their parent is A.
  3. Remove B. A is already discovered. Discover D and E at distance 2; queue = [C, D, E]. Their parent is B.
  4. Remove C. A and E are already discovered; queue = [D, E].
  5. Remove D. B and E are already discovered. Discover F at distance 3, with parent D; queue = [E, F].
  6. Remove E. Its neighbors B, C, D, F are already discovered; queue = [F].
  7. Remove F. D and E are already discovered; the queue becomes empty.

Result: distance(A)=0, distance(B)=distance(C)=1, distance(D)=distance(E)=2, distance(F)=3. The BFS tree contains A–B, A–C, B–D, B–E, D–F. One shortest path to F is A → B → D → F, containing three edges.

Invariant: vertices leave the queue in nondecreasing distance order. Discovering a neighbor of a distance-d vertex assigns distance d+1. Marking on enqueue prevents duplicate queue entries.

Kruskal: the cut and cycle properties

For a connected, weighted, undirected graph, Kruskal builds a minimum spanning tree by scanning edges from lightest to heaviest. Accept an edge only when it joins two different components. The accepted edges always form a forest. Sorting dominates the runtime: O(|E| log |V|) for a simple graph, with union–find tracking the components.

Enable JavaScript for the interactive graph, or read the complete walkthrough below.

Graph and complete Kruskal walkthrough

Vertices: A, B, C, D, E. Edges and weights in sorted order: A–B (1), B–C (2), B–D (3), A–C (4), C–D (5), D–E (6), C–E (7).

  1. Start with components {A}, {B}, {C}, {D}, {E}.
  2. Accept A–B (1), joining A and B. Total weight = 1.
  3. Accept B–C (2), joining {A,B} and {C}. Total weight = 3.
  4. Accept B–D (3), joining {A,B,C} and {D}. Total weight = 6.
  5. Reject A–C (4). A and C are already connected through B, so this edge would create the cycle A–B–C–A.
  6. Reject C–D (5). C and D are already connected through B, so this edge would create the cycle C–B–D–C.
  7. Accept D–E (6), joining {A,B,C,D} and {E}. Total weight = 12.
  8. Reject C–E (7). Its endpoints are already connected. The algorithm could instead stop as soon as four edges were selected.

Result: the MST is {A–B, B–C, B–D, D–E}, with total weight 1+2+3+6=12 and |V|−1=4 edges.

Cut property: a lightest edge across a cut that respects the current forest can safely extend that forest to an MST. Each accepted edge joins two components and is lightest across such a cut.

Cycle property: a uniquely heaviest edge on a cycle belongs to no MST. All weights in this example are distinct. With tied weights, rejecting an edge that forms a cycle still preserves Kruskal’s correctness, but that rejected edge may belong to a different MST.

Maximum flow: residual capacity and augmenting paths

A flow respects every directed edge’s capacity and conserves flow at all vertices except the source s and sink t. For an original edge u → v with capacity c and flow f, the residual graph has forward capacity c−f and reverse capacity f. Reverse arcs allow earlier flow to be canceled. Edmonds–Karp uses BFS to choose a shortest augmenting path in the residual graph and runs in O(|V| |E|²).

Network and complete maximum-flow walkthrough

Vertices: s, a, b, t. Directed capacities: s → a = 3, s → b = 2, a → b = 1, a → t = 2, b → t = 3. Every initial flow is 0. The drawing labels original edges as flow/capacity; the state table also lists both forward and reverse residual capacities.

  1. BFS in the residual graph finds s → a → t. Its residual capacities are 3 and 2, so augment by min(3,2)=2. The flow value becomes 2.
  2. The next shortest residual path is s → b → t. Its residual capacities are 2 and 3, so augment by 2. The flow value becomes 4.
  3. The next path is s → a → b → t. Its residual capacities are 1, 1, 1, so augment by 1. The flow value becomes 5.
  4. No residual path from s reaches t. Both edges leaving s are saturated, so the residual reachable set is {s}. The cut from {s} to {a,b,t} has capacity 3+2=5.

Final flow: s → a: 3/3; s → b: 2/2; a → b: 1/1; a → t: 2/2; b → t: 3/3. At a, incoming 3 equals outgoing 1+2. At b, incoming 2+1 equals outgoing 3. Source outflow and sink inflow are both 5.

Optimality certificate: the flow value equals the capacity of the cut ({s}, {a,b,t}), so max-flow/min-cut proves this flow is maximum. This small example creates reverse residual arcs but never needs to use them; other networks can require rerouting along a reverse arc.
